# DSH 0.2.1-rc.3 compatibility

DSH `0.2.1-rc.3` is a prerelease. This plugin line targets the exact official
tag `dsh-v0.2.1-rc.3` at
[`1f81c047fc48fa190a683e469daa699857e9afe8`](https://github.com/deepseek-ai/deepseek-harness/commit/1f81c047fc48fa190a683e469daa699857e9afe8).
It is not a recommendation to upgrade a production Core or Desktop.

## Verified source differences

The public [`WebRuntime` source at the pinned commit](https://github.com/deepseek-ai/deepseek-harness/blob/1f81c047fc48fa190a683e469daa699857e9afe8/packages/web/web/src/index.ts)
requires both `searchProvider` and `fetchProvider` as `Volatile<string |
undefined>` configuration values and reads each with `.get()`. The constructor
requires the config object rather than defaulting to `{}`. Passing the old
plain-string object can fail typechecking and can reach `.get is not a
function` at runtime. The plugin therefore supplies plugin-owned, read-only
`get()` references to its bounded runtime and passes explicit config to the
wrapped public runtime.

The experimental Auto reviewer remains qualified only when the package owner,
exact package version and imported `apply` callback match the native Loader
root. The exact rc.3 source fixture exercises that identity boundary; adding a
version string alone is not sufficient evidence.

The rc.3 source metadata pins Cordis `4.0.5`, cordis-plugin-loader `1.0.6`,
schemastery `3.18.5`, pi-ai `1.1.0` and Zod `4.4.3`. The plugin uses those
exact framework/schema versions for this target.

## Qualification status and limits

The Windows/Linux CI configuration is required to run both the unchanged
tagged-source regression suite and an isolated fixture against exact published
rc.3 artifacts. The fixture verifies package versions, peer resolution, public
class identity, typechecking and synthetic adapter/reviewer behavior. It makes
no real sign-in or provider request.

[CI 40098031196](https://github.com/cloga/dsh-github-copilot/actions/runs/40098031196)
passed on commit `ec4037601f8d183a711bb0e4dd4048a4e382085e`:

- Windows/Linux unchanged tagged-source: 466 passed, two retained legacy-only
  skips; native rendering seven passed and configuration three passed.
- Windows/Linux exact published artifacts: 501 passed, two retained legacy-only
  skips. All 28 native reviewer regressions passed without skips in each
  source/artifact population.
- Windows/Linux full `pnpm verify`: 2,775 Vitest tests passed, two existing
  skips; all 386 tooling tests, types, build and package-entry smoke passed.
  `pnpm pack --pack-destination artifacts` and verification of the exact archive
  passed on both platforms. The branch release job was skipped, not published.

The last full-gate blocker was an offline maintenance-tool assumption: current
Node 24 decompresses concatenated Zstandard frames together. The tool now scans
standard physical frame boundaries before native per-frame decompression,
preserving native checksum/catalog validation, independent header framing,
source hashes and detached-copy-only output. Four structural regression tests
include truncation, RLE/windowed frames and a 65,536-frame work bound. No
real history was read, repaired or replaced to produce this evidence.

The same run includes [#433](https://github.com/cloga/dsh-github-copilot/issues/433):
cold-open scheduled replay-scope failures retain a native-terminal-evidence
entry to the existing explicit continuation policy control. Missing ephemeral
request fingerprints do not fabricate diagnostics or authorize old fingerprint
recovery. Enabling remains a loss-disclosed user action; no automatic policy
change, task retry, account fallback or stored-history mutation is introduced.

The exact rc.3 lockfile was generated by the read-only, branch-scoped
[official-registry recovery job](https://github.com/cloga/dsh-github-copilot/actions/runs/40094706349)
using pnpm 11.7.0 with the unchanged package-age policy and strict peers. Its
original artifact was adopted byte-for-byte (SHA-256
`df7130ad5ea00ab39c78cd898d2ac6c8fda8020e29e6be6cd57d555d2dd60d73`).
That job verified that the rc.3 packages exist on npm. In particular,
`@deepseek-ai/dsh-agent@0.2.1-rc.3` was published at
`2026-10-23T07:34:46.254Z`, earlier than the GitHub Release. The earlier
release-age explanation based on the GitHub timestamp was unverified and is
superseded by this registry evidence.

Local frozen installation accepts the synchronized lockfile but the configured
enterprise mirror returns HTTP 404 for the exact rc.3 tarball; direct npm access
fails TLS. This is a local validation limitation, not an absent official
artifact. The unchanged official-registry CI is the qualification path; no
substitutions, registry-policy bypass, age-policy changes or fabricated
integrity values are used.

Desktop artifacts/signatures and runtime package composition are unverified.
No live install, restart, credential flow or model/search request is authorized
or implied. No DSH Core source, build or dependency artifact is changed.
